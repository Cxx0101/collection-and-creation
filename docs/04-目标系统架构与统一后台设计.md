# 04 · 目标系统架构与统一后台设计（非 SaaS 版）

根据项目定位：**不做多租户 SaaS（无组织/子账号体系），支持普通用户自主注册使用，由一个统一管理后台集中配置对象存储（OSS/TOS/COS）、TikHub 采集渠道、平台大模型、积分套餐与消费单价；前端用户共用一个积分池进行平台大模型创作与 TikHub 按页采集，同时保留用户自行接入自有大模型的能力。**

> 实施说明：当前版本以 MySQL 任务表 + 内置 Go Worker 驱动异步任务，以 JWT + `token_version` 处理会话失效，未引入 Redis/Asynq；涉及队列与会话的章节以当前实现为准。

---

## 一、核心定位与权限模型（RBAC）

系统仅设两类角色，采用简洁的 RBAC 鉴权模型：

| 角色 | 账号来源 | 核心权限边界 |
| --- | --- | --- |
| **`admin`（系统管理员）** | 首个初始化账号（通过环境变量 `ADMIN_INIT_PHONE` / `ADMIN_INIT_PASSWORD` 或 `./studio-server init-admin` CLI 初始化，禁止硬编码弱口令）或由管理员提升 | 访问**统一管理后台 `/admin/*`**；管理用户与重置密码、OSS/TOS/COS 存储、TikHub 采集与每页积分、平台大模型及生图/生视频积分定价、积分套餐与充值调账、全站任务监控 |
| **`user`（注册用户）** | 手机号 + 密码自主注册（**无需审核直接激活**；后台可设定**是否开启短信验证码**、**是否赠送初始积分**） | 访问**C 端创作平台**；可使用注册赠分与**支付宝/微信在线充值积分**调用平台采集与大模型，也可在个人中心自由新增/编辑多套**自有大模型供应商、微信公众号**；独立增删改查个人采集、产品、技能、资产、复刻草稿与工作流 |

## 二、四大核心运行机制设计

### 2.1 媒体存储引擎（后台统一配置：OSS / TOS / COS）
- **全局统一配置**：存储引擎仅在管理员后台 `/admin/storage` 配置，全站用户资产统一托管至管理员指定的云端存储，无需普通用户接触存储密钥。
- **三引擎支持**：在 Go 后端中统一抽象 `ObjectStorage` 接口（`Put`、`Get`、`Delete`、`SignedURL`、`PresignPut`），接入 **阿里云 OSS（`aliyun-oss-go-sdk`）**、**火山引擎 TOS（`ve-tos-golang-sdk`）** 与 **腾讯云 COS（`cos-go-sdk-v5`）**，并可保留本地共享挂载卷作为开发兜底。
- **全媒体统一转存对象存储**：除用户上传素材与产品图外，**TikHub 采集到的作品封面图/图文原图、文章生成配图、外部视频/生图模型返回的结果 URL** 均由服务端下载校验 MIME/魔数并转存至统一对象存储（防外链过期及 `403` 防盗链裂图），同步记录 `assets` 表。其中 AI 生成结果必须转存成功才流转任务为 `succeeded`；TikHub 采集封面若因单条防盗链超时，允许记录失败标记并异步补抓而不整批回滚。Bucket 需配置浏览器 CORS 规则（`PUT`/`GET`/`HEAD`），同时提供服务端 `/api/v1/assets/upload` 中转上传兜底；Worker 定期运行对象存储 GC 清理超时未提交上传与超过保留期的软删文件。

### 2.2 大模型双轨机制（平台统一接口 vs 用户自有接口）
- **轨道 A · 平台统一大模型接口（后台集中接入，前端按积分调用）**：
  - **借鉴原项目多供应商配置机制并升级为多实例 CRUD**：管理员可在 `/admin/providers` 针对 `ark`、`deepseek`、`glm`、`openai`、`google`、`midjourney`、`minimax`、`kling`、`qwen` 及自定义 `custom`（OpenAI 兼容接口）**自由新增、编辑、停用与删除多个供应商接入实例**（支持设置显示名称、API Base URL、API Key / 可灵 AK+SK、自动保存并拉取远端模型列表或预设清单、为每个模型打标 `understanding`/`image`/`video` 能力类型，并设置全局默认理解/生图模型）；
  - 为每个对前端开放的**生图模型、生视频模型**（以及可选的理解/分析模型）配置**积分消耗规则**；
  - 前端用户无需填写任何 API Key，账户充值积分后即可直接调用平台接口。
- **轨道 B · 用户自有大模型接口（前端个人配置，直连免积分）**：
  - 保留用户在个人中心自由**新增、编辑、拉取模型、启用/停用、删除多个自有大模型供应商**的功能（兼容原项目同款协议选择 + 自定义 OpenAI 兼容端点，支持填写 API Key / 可灵 Secret Key、模型能力打标，AES-256-GCM 加密存储于 `user_provider_configs`）；
  - 对普通用户填入的 `base_url` 实施严格 SSRF 校验（仅允许公网 HTTPS，禁止内网 IP 与回环地址）。
- **前端统一选择与路由解析**：
  - 创作页、复刻页、工作流节点的模型下拉框按来源清晰分组：**「平台接口（显示预计消耗积分）」** 与 **「我的自定义模型（使用自有 Key · 0 积分）」**；
  - **复刻页面全面开放可选模型与能力目录驱动**：移除原前端对 `ark` / `comfyui` 的硬编码限制及全局默认锁死，覆盖全部 10 类云端供应商（`ark`、`deepseek`、`glm`、`custom`、`openai`、`google`、`midjourney`、`minimax`、`kling`、`qwen`）。只要后台已配置可用供应商参数（或用户在个人中心自行配置），视频复刻与图文复刻均允许用户自由选择对应模型；服务端统一下发**模型能力目录**（是否支持视频参考/首尾帧、最大参考图数、最长时长、支持比例与分辨率），前端按所选模型动态渲染参数控件（不支持直接视频参考的视频模型自动引导走「分镜/首帧图生视频」路径）；
  - **复合任务分环节计费**：视频复刻、图文复刻、产品图生视频、公众号文章配图等复合链路拆分为「理解模型」与「生成模型」独立选项，仅对选用平台接口的环节进行积分冻结与结算；
  - 任务提交时记录 `model_source = "platform" | "user_custom"` 及 `provider_config_id`，Worker 执行时据此决定读取平台加密凭证并扣费，还是读取用户加密凭证且跳过积分扣除。

### 2.3 平台采集机制（统一后台接入 TikHub + 按页扣积分）
- **统一接入 TikHub**：移除原系统的插件中心登录授权与客户端采集网关，由管理员在 `/admin/collection` 统一配置 **TikHub API Key**、接口 Base URL、**可选网络代理（用于国内服务器下载 TikTok 视频）**、各平台开关及热度权重。
- **按采集页数扣费与上限控制**：后台设置**“采集一页扣除多少积分”**（支持统一单价或按平台分别设定每页积分 `credits_per_page`），沿用原系统 `MAX_COLLECTION_PAGES = 30` 与停滞去重终止规则（连续 2 页无新 ID 或上游返回 `has_more = false` 自动结束）。提交采集时可传入目标条数 `limit`（1–500）与最大页数预算 `max_pages`（不超过 30），前端提交前明确展示「最多预冻结 `max_pages × 单页积分`」，任务结束严格按 **实际成功向上游发起且返回响应的 TikHub 页数 `pages_fetched`** 结算（**注：即使已拉取 `N` 页但经视频时长/互动过滤后可用条数为 0，仍须按实际消耗的 `N` 页结算，仅退还剩余未拉取页数**；若第 1 页即报错未成功拉取或未执行前取消，则全额退回）。
- **视频链接兜底解析**：视频复刻/分析获取源视频时，按「已有采集直链 -> `yt-dlp` -> TikHub 单视频直链刷新接口（可选配置单次积分，默认 `0` 免费兜底）」顺序尝试。

### 2.4 共用积分池、充值套餐与事务级扣费闭环
- **单一共用积分池**：每位用户拥有一个统一积分钱包（`credit_wallets`：`available_credits` 可用余额 + `frozen_credits` 冻结余额），**TikHub 采集、平台生图模型、平台生视频模型（及平台理解模型）全部共用这一积分池**。
- **积分套餐与支付宝 / 微信直充闭环（无卡密模式）**：
  - **后台套餐自定义 CRUD 与支付配置**：管理员在 `/admin/credits` 可对积分套餐进行完整的**新增、编辑、排序、上下架与删除**（自定义套餐名称、角标、售价、基础积分、赠送积分与说明），并在支付通道配置页设置**支付宝（当面付 / 网页支付）**与**微信支付（Native 扫码 / JSAPI）**商户参数及异步回调地址，同时保留管理员对用户积分的手工调账（增/减）与异常订单人工核销补单能力；
  - **C 端极简充值与收银台流程**：用户在 `/credits` 选择套餐与支付方式（**支付宝 / 微信支付**），进入独立支付收银台完成扫码或跳转支付，服务端在验签通过后通过数据库幂等事务即时入账并更新状态，用户可随时查看充值订单与积分消费流水。
- **精准定价规则（`model_pricing_rules`）**：
  - **生图模型**：可按“每次/每张固定积分”配置（如 `image_batch_count` 乘单价），亦可区分分辨率档位；
  - **生视频模型**：可按“每次固定积分”或“基准积分 / 每秒单价 × 时长 + 分辨率系数”（如 720p vs 1080p）配置，提交前前端实时试算并展示预估扣分；
  - **费率快照与部分成功结算**：任务提交瞬间将命中规则的单价/系数快照写入任务与流水 `detail_json`，后续管理员调价不影响已入队任务；批量生图或套图任务（`per_item` 计费）按实际成功出图张数核销，失败槽位自动退还冻结积分；
  - **采集任务**：提交时按 `预期最大页数 × 每页单价` **预冻结**（或校验最低可用门槛后按页实时扣减），任务结束按 **实际成功拉取的 TikHub 页数** 精确结算，未拉取页数对应冻结积分立即退回可用余额。
- **账本状态机（防错扣/漏扣）**：
  - 任务创建时在 MySQL 事务内使用 `SELECT ... FOR UPDATE` 锁定钱包行并携带唯一 `idempotency_key`，校验余额并写入冻结流水（`reserve`）；
  - 任务成功时将冻结转为实际扣款（`settle`）；
  - 任务失败、取消或提前终止（如采集中途无更多数据）时自动触发退额（`refund` / `release`），全部流水记入不可篡改的 `credit_transactions` 账本；定时工作流若遇余额不足直接失败停跑并通知用户，不做无限重试。

### 2.5 账号注册、密码找回与公众号绑定规则
- **注册与验证码策略**：采用手机号 + 密码注册，无需人工审核直接激活；后台 `/admin/users` 可控制开放注册开关、短信验证码开关（开启时强制 60 秒冷却、单 IP/手机号日限流与错码熔断）及新用户赠送积分。
- **忘记密码与会话失效**：当后台**关闭短信验证码**时，登录页「忘记密码」展示后台可配置的“联系管理员重置密码”指引文案，由管理员在 `/admin/users` 重置密码；当后台开启短信网关时开放短信验证码找回。**无论管理员重置密码还是禁用账号，均立即递增 `users.token_version` 并清理缓存，使该用户所有历史 JWT 立即失效**。
- **个人第三方绑定**：用户在 `/profile` 自主绑定自有大模型 Key 与微信公众号（AppID/AppSecret AES-GCM 加密）。绑定弹窗展示当前服务器出口 IP 一键复制提示（引导加入微信公众平台 IP 白名单）；当前版本保存绑定配置与启停状态，`stable_token` 缓存与文章发表接口按后续需求扩展。

## 三、业务数据的个人归属边界
- **全业务数据严格个人私有**：`source_items`（采集素材）、`collection_batches`、`collection_keywords`、`products` / `product_images`、`assets`、`video_assets`、`jobs`、`clone_drafts`、`article_publications` 全部严格按 `owner_user_id` 隔离，**采集与创作数据仅会员自己可见**（`source_items` 按 `(owner_user_id, platform, external_id)` 去重）。
- **个人第三方账号自主绑定**：微信公众号多账号（`user_wechat_accounts`）与个人自有大模型配置（`user_provider_configs`）均由用户在个人中心自行绑定管理（AES-256-GCM 加密落库），后续扩展其他个人平台账号也沿用“用户自主绑定”原则。
- **工作流计划**：复用原系统中已有的 `principal_ref` 字段语义，直接映射为 `owner_user_id`；工作流节点执行时同样遵循 `model_source` 扣费或免扣规则，并在预检（`preflight`）阶段提示预计积分消耗。

## 四、页面与路由重构规划

彻底脱离原单机版内部工具表单页面，按**面向 C 端的内容创作平台**重构信息架构，划分为 **C 端用户平台界面** + **独立统一管理后台**：

### 4.1 C 端平台前端界面（独立于后台，纯面向 C 端创作者）
1. `/login` & `/register`（视觉化分栏登录/注册弹窗或独立页）：手机号 + 密码登录与自主注册（根据后台开关动态显隐短信验证码；关闭短信时「忘记密码」展示后台可配的联系管理员重置密码指引；注册后直接激活登录）。
2. `/`（灵感广场 · 平台首页）：采用 C 端 **Hero 提示词/链接一键输入框 + Bento 能力矩阵 + 精选模板瀑布流**，不混入后台入口，流程极简，点击卡片一步直达创作或复刻。
3. `/collect`（爆款采集中心）：极简检索栏（平台 + 关键词/AI提炼 + 页数预算）+ 私有采集库瀑布流（支持详情查看、批次/单条删除、一键送去复刻）+ 个人关键词库增删管理。
4. `/studio`（AI 创作工坊 · 全 13 项能力）：三栏 Studio 交互（左侧 13 项能力目录 + 中间浅色创作输入台/涂抹画布/公众号手机排版预览，不展示输出图片列表；产物统一存入个人资产库 + 右侧双轨模型选择、参数配置与 `@技能` 增删改查管理）。
5. `/clone`（爆款复刻工作台）：极简 3 步流（选爆款/贴链接 → 绑商品 & 自由选任意云端模型 → 预览分镜/九宫格/图文文案并生成），支持草稿保存、编辑、文案重试与删除。
6. `/library`（商品 · 资产 · 自动化计划）：完整的个人内容 CRUD 空间——**个人资产库**（上传、预览、删除、批量 ZIP、再创作）、**我的商品库**（多图产品新增/编辑/删除）、**自动化流水线**（DAG 编排新建/编辑/启停/删除与余额不足停跑保护）。
7. `/credits` & `/credits/checkout`（积分充值与独立支付收银台）：共用积分钱包余额、套餐卡片挑选、**支付宝 / 微信支付独立收银台页面（扫码/跳转 + 订单状态实时刷新）**、个人充值订单与积分消费流水明细。
8. `/profile`（个人设置与第三方绑定）：资料与改密、**我的自定义大模型多供应商 CRUD（新增/编辑/拉取模型/能力打标/启停/删除）**、**我的微信公众号多账号 CRUD（显眼展示服务器出口 IP 一键复制）**。

### 4.2 统一管理后台（`/admin/*`，仅 `admin` 角色可见）
1. `/admin/overview`：全站用户数、充值金额/积分消耗统计、今日任务数、Worker/存储/支付通道健康度。
2. `/admin/users`：用户列表与完整 CRUD（检索、新增/编辑、启用/禁用、重置密码并踢出旧 Token、并发配额与手工调账），以及全局注册与短信策略配置。
3. `/admin/credits`：**积分套餐完整 CRUD**（新增、编辑、排序、上下架、删除）、**支付宝与微信支付通道参数配置**（AppID/商户号/密钥/回调验签）、全站充值订单查询与异常人工补单/退款处理。
4. `/admin/providers`：**多供应商大模型接入与定价 CRUD**（借鉴原项目：支持对 `ark`/`deepseek`/`glm`/`openai`/`google`/`midjourney`/`minimax`/`kling`/`qwen`/`custom` 新增多个实例、编辑 Base URL/API Key/SK、拉取远端模型、模型能力打标、全局默认模型指定，以及模型积分定价规则 CRUD）。
5. `/admin/collection`：**TikHub 接口配置**（API Key / 域名 / 可选出口代理 / 各平台开关）、**按平台或全站每页积分单价设置**与热度权重配置。
6. `/admin/storage`：**存储引擎统一设置（阿里云 OSS / 火山引擎 TOS / 腾讯云 COS）**、CORS 检查、连通性测试与同步/GC 状态。
7. `/admin/jobs`：全站异步任务与定时工作流监控、日志详情排查、强制取消与积分退费核销。

## 五、核心数据库改造清单（基于原 26 张表精简重构）

1. **剔除 2 张退役历史表**：移除 `publication_plans`、`publication_batches`。
2. **新增核心基础表（13 张）**：
   - `users`：`id`、`phone`（唯一索引 `VARCHAR(32)`）、`nickname`、`password_hash`、`role`（`admin`/`user`）、`status`（`active`/`disabled`）、`token_version`（密码重置/禁用即时踢下线）、`quota_json`、`created_at`、`last_login_at`。
   - `sms_verification_codes`：`id`、`phone`、`scene`（`register`/`reset_password`）、`code_hash`、`expires_at`、`used_at`、`created_at`（后台开启短信验证码时使用）。
   - `system_settings`：`key`、`value_json`、`updated_by`、`updated_at`（承载注册总开关/短信验证码开关/注册赠分/联系管理员文案、短信网关配置、**支付宝与微信支付通道加密配置**、全局默认模型、TikHub 采集与每页单价、热度权重、OSS/TOS/COS 存储配置）。
   - `provider_configs`（平台多实例大模型配置）：`id`、`provider`、`display_name`、`base_url`、`models_json`、`model_types_json`、`encrypted_credentials`（服务端 AES-GCM 密文，含 `api_key` 与可灵 `secret_key`）、`is_custom`、`sort_order`、`enabled`、`created_at`、`updated_at`。
   - `user_provider_configs`（用户多实例自有大模型配置）：`id`、`owner_user_id`、`provider`、`display_name`、`base_url`、`models_json`、`model_types_json`、`encrypted_credentials`、`enabled`、`created_at`、`updated_at`。
   - `model_pricing_rules`（平台模型消费定价）：`id`、`rule_key_hash`（`CHAR(64)` 唯一索引）、`provider`（`VARCHAR(32)`）、`model_id`（`VARCHAR(120)`）、`capability_kind`（`image`/`video`/`understanding`）、`billing_mode`（`per_call`/`per_item`/`per_second`）、`base_credits`、`unit_credits`、`spec_multipliers_json`（如分辨率/模式系数）、`enabled`、`updated_at`。
   - `credit_wallets`（用户共用积分池）：`user_id`（主键）、`available_credits`、`frozen_credits`、`total_recharged`、`total_consumed`、`updated_at`。
   - `credit_packages`（积分充值套餐 · 支持完整 CRUD）：`id`、`name`、`badge_text`、`description`、`price_cents`、`credits`、`bonus_credits`、`sort_order`、`enabled`、`created_at`、`updated_at`。
   - `credit_orders`（充值订单 · 支付宝/微信直充）：`id`、`order_no`（唯一索引 `VARCHAR(64)`）、`user_id`、`package_id`、`amount_cents`、`credits_granted`、`bonus_credits`、`channel`（`alipay`/`wechat`/`manual_admin`）、`status`（`pending`/`paid`/`closed`/`refunded`）、`pay_qr_url`、`external_trade_no`（唯一索引）、`paid_at`、`expires_at`、`created_at`。
   - `credit_transactions`（积分流水账本）：`id`、`user_id`、`kind`（`register_bonus`/`recharge`/`admin_adjust`/`reserve`/`settle`/`refund`）、`biz_type`（`tikhub_collect`/`image_generate`/`video_generate`/`understanding`/`payment_order`）、`biz_id`（关联 `jobs.id` 或 `credit_orders.id`）、`delta_available`、`delta_frozen`、`balance_after`、`detail_json`（记录采集页数、单页价、模型 ID、支付流水号等明细）、`idempotency_key`、`created_at`。
   - `assets`：`id`、`owner_user_id`、`kind`（`image`/`video`/`markdown`）、`source_type`（`upload`/`generated`/`product`/`source_video`）、`storage_provider`、`object_key`、`original_name`、`mime_type`、`size_bytes`、`width`、`height`、`duration_seconds`、`meta_json`、`created_at`、`deleted_at`（替代原磁盘遍历与 `storage-index.sqlite3`）。
   - `creation_skills`：`id`、`owner_user_id`（内置只读技能为 `NULL`）、`name`、`description`、`content_md`、`size_bytes`、`sha256`、`is_builtin`、`created_at`、`updated_at`（替代原本地 `.data/creation-skills/` 文件库，支持按用户隔离导入的 `.md` 技能）。
   - `user_wechat_accounts`：`id`、`owner_user_id`、`app_id`（`VARCHAR(64)`）、`account_name`、`encrypted_app_secret`、`enabled`、`created_at`、`updated_at`（唯一键 `(owner_user_id, app_id)`）。
3. **原有业务表补齐归属字段与索引**：
   - 为 `source_items`、`collection_batches`、`collection_keywords`、`jobs`、`products`、`video_assets`、`clone_drafts`、`article_publications` 增加 `owner_user_id`（外键关联 `users.id`）及复合索引 `(owner_user_id, created_at)`；`source_items` 新增 `source_key_hash CHAR(64)` 建唯一索引（`SHA256(owner_user_id:platform:external_id)`，规避 MySQL 5.7 联合索引超 767 字节限制）。
   - `jobs` 增加显式列 `sub_type`（如 `image_tool` 值）、`model_source`、`billing_mode`、`reserved_credits`、`settled_credits`（避免在 MySQL 5.7/8.0 中通过 JSON 路径字段做过滤查询）；`collection_batches` 记录 `pages_fetched` 与 `credits_charged`。
   - `workflows`、`workflow_plans`、`workflow_commands` 复用现有 `principal_ref` 字段直接存 `user.id`。
4. **MySQL 8.0 向下兼容 MySQL 5.7 建表与查询规范**：
   - **字符集与排序规则**：全库全表统一显式声明 `ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci`（严禁使用 MySQL 8.0 默认的 `utf8mb4_0900_ai_ci` 导致 5.7 导入失败）。
   - **索引长度安全**：显式声明 `ROW_FORMAT=DYNAMIC`，所有单列或组合索引的总键长严格控制在 `767` 字节以内（如长路径/长组合键统一派生 `CHAR(64)` 哈希列建唯一索引），主键统一 `CHAR(36)` 或自增 `BIGINT`。
   - **SQL 语法约束**：禁止在迁移和业务查询中使用 `WITH` CTE、窗口函数与 `SELECT ... FOR UPDATE SKIP LOCKED`；任务认领采用带状态条件的原子 `UPDATE` 加行数判断，兼容 MySQL 5.7；`JSON` 列不设数据库 `DEFAULT` 值，由 Go 层初始化写入。

## 六、推荐工程与部署结构（轻量化一键部署）

配合**宝塔面板（BT Panel）+ Go 语言后端**，前后端彻底解耦、后端以轻量单二进制交付运行，无需在生产环境安装 Python 依赖栈：

```text
项目根目录/
├── frontend/                 # 独立 React + TypeScript + Vite SPA（含 /admin 后台模块）
│   ├── src/pages/workspace/  # 前台创作工作台 + 积分充值 + 个人自定义模型中心
│   ├── src/pages/admin/      # 统一管理后台 7 大模块（含存储三引擎/TikHub/套餐/模型定价）
│   └── dist/                 # 构建后直接部署至宝塔 Nginx 静态站点
├── backend/                  # Go 模块工程（Gin + GORM + 内置 Worker）
│   ├── cmd/
│   │   ├── server/           # HTTP API 服务入口（宝塔 Go 项目 / Supervisor 托管）
│   │   └── worker/           # 异步任务 Worker + 定时工作流 Scheduler 入口
│   ├── internal/
│   │   ├── api/              # 路由、鉴权中间件、积分账本与 /admin 管理接口
│   │   ├── domain/           # 热度算法、分镜规则、图像工具、工作流 DAG 编译校验
│   │   ├── service/          # 业务编排、积分预冻结/结算/退费事务、任务提交
│   │   ├── adapter/          # 10 类大模型、TikHub 采集、公众号 API、OSS/TOS/COS 适配
│   │   ├── media/            # 封装调用服务器 FFmpeg / FFprobe / yt-dlp 与图片处理
│   │   └── model/            # GORM 数据模型与数据库迁移（migrations/）
│   └── go.mod
└── deploy/
    └── bt/                   # 宝塔 Nginx 反代模板、Supervisor 守护配置与环境变量样例
```
