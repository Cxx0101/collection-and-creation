## 核心分析结论

- **前后端分离重构策略**：前端页面**不再参考原项目内部工具表单流**，而是以 **React 19 + TypeScript + Vite** 从零构建**面向 C 端内容创作者的平台型产品界面**（灵感广场 / 爆款采集 / 创作工坊 / 复刻工作台 / 资产商品 / 积分绑定 + 独立管理后台）；原后端 Python（FastAPI）仅作为**协议与领域规则蓝本**，统一采用 **Go 语言**重构为高性能无状态 API 与分布式 Worker。
- **网页化的本质是“去单机化 + 统一后台治理”**（不做复杂 SaaS 多租户/计费隔离）：
  1. **认证与归属**：取消插件中心单机设备绑定与内存 `_sessions` 字典，改为**手机号 + 密码注册/登录**（无需审核直接激活，后台可控制短信验证码开关与新用户注册赠分；关闭短信时支持管理员后台重置密码并立即踢出旧会话），所有业务表与采集数据均按 `owner_user_id` 严格私有隔离。
  2. **数据库与队列**：告别本地 `SQLite`（及 `storage-index.sqlite3`），采用宝塔原生支持的 **MySQL 8.0（同时严格兼容 MySQL 5.7）**；采集、创作、复刻与工作流任务统一落库，由内嵌 Go Worker 每 2 秒原子认领并并发执行，失败自动退回预冻结积分。
  3. **存储与采集集中配置**：后台统一管理 **阿里云 OSS / 火山引擎 TOS / 腾讯云 COS** 三类对象存储引擎与 **TikHub** 上游采集接口，采集封面/图文与生成结果均统一转存对象存储；取消 `powershell.exe` 本地弹窗导出，改为对象存储直传与浏览器单图/ZIP 打包下载。
  4. **大模型双轨制与共用积分池**：后台支持按协议自定义新增/编辑多实例云端大模型供应商（借鉴原项目模型拉取与能力打标机制），并为生图、生视频模型及 TikHub 按页采集配置积分单价；充值采用**支付宝 / 微信支付直充模式**（后台自定义增删改查积分套餐并配置支付通道参数），创作与复刻支持自由选择平台接口或个人中心自定义绑定的多模型供应商。
  5. **功能范围精准收敛**：完整开发前端已展示的全部功能（含 4 类内容创作、6 类 POD 素材、3 类 AI 修图共 13 项创作能力，以及采集/产品/复刻/计划/资产/个人中心），原后端未在界面入口展示的 4 项修图（裁剪/抠图/放大/扩图）不纳入开发。
  6. **桌面与本地依赖剥离**：移除 Electron 主进程、托盘生命周期、在线安装包更新（`/api/desktop-updates/*`）、本地 `codex-director.mjs` CLI、Playwright 浏览器采集、本机 ComfyUI、`@hypit/hypit` 及视频硬字幕烧录流水线。
- **建议同步裁剪的历史包袱**：原库仍保留 5 个已退役的多平台自动发布 `JobType`、`publication_plans` / `publication_batches` 历史表、`410` 状态的旧版浏览器采集兼容接口，以及 4 个已退役工作流发布节点，新系统整合时可直接剔除。

### 合众纵横（Fyepay）聚合支付

在管理后台「积分套餐与支付通道」页面的 **Fyepay · 合众纵横聚合收款** 卡片填写商户配置。启用且商户号、商户密钥完整后，前台支付宝与微信充值的二维码订单会优先走 Fyepay；关闭后改用下方支付宝/微信官方直连通道。

| 配置项 | 说明 |
| --- | --- |
| `payment.fyepay.mchId` | 合众纵横分配的商户号 |
| `payment.fyepay.key` | 商户密钥，服务端使用 AES-GCM 加密保存且不回显；留空保存不会覆盖旧密钥 |
| `payment.fyepay.gateway` | 默认 `https://api.fyepay.com/getaway` |
| `payment.fyepay.tradeIp` | 可选。渠道要求固定交易 IP 时填写服务器公网 IPv4 |
| `payment.fyepay.notifyUrl` | 可选。留空时自动使用 `PUBLIC_BASE_URL/api/v1/payments/fyepay/notify` |

生产环境的 `PUBLIC_BASE_URL` 必须是外部可访问的 HTTPS 地址，且回调路径 `/api/v1/payments/fyepay/notify` 不能被宝塔防火墙、Nginx 鉴权或 CDN 拦截。前台创建订单后会每 4 秒轮询支付状态；除异步回调外，系统还会调用 Fyepay 查单接口兜底入账，重复通知不会重复加积分。

### 视频模型分辨率定价

火山方舟不是按固定的 480P/720P/1080P 三档包价收费，而是按实际输出视频 token 计费。官方计费文档给出的输出 token 公式为：

```text
输出视频 token = 视频时长（秒）× 帧率 × 宽 × 高 ÷ 1024
```

因此同一画幅、同一帧率下，分辨率越高，输出 token 越多：480P 约为 720P 的 0.44 倍，1080P 约为 720P 的 2.25 倍。管理后台的模型定价表单允许分别设置三档每秒积分；某档留 `0` 时回退到基础积分单价。前台只展示三档选项，当前模型不支持的档位会禁用。参考文档：[火山方舟视频生成计费](https://www.volcengine.com/docs/82379/1544106?lang=zh)。

当前工程未保存真实商户凭据，也没有发起真实扣款。接入后请先关闭模拟支付，在 `APP_ENV=production` 下使用最小金额套餐完成一笔真实支付、一笔超时未支付和一次重复异步通知验证。
